# etask — от цели проекта до выполненных задач

**Плагин для Codex, Claude Code и Gemini CLI, который помогает агенту вести
разработку по согласованному процессу.**

Ты описываешь цель проекта. Агент предлагает задачи, ведёт Markdown-доску,
планирует изменения, проверяет код и сохраняет контекст для продолжения работы.

```text
Цель → задачи → согласованный план → реализация
                ↑                       ↓
         исправления ← review + санитайз → тесты → результат
```

Работает локально или с GitHub. **Jira необязательна.**
GitHub нужен только при явно выбранном режиме github.

## Что ты получаешь

- **Цель проекта и понятный список задач.** У каждой задачи есть ID, критерии
  готовности и зависимости.
- **Доску прямо в проекте.** Markdown можно читать в редакторе и переносить
  вместе с файлами проекта.
- **Контроль качества после каждой правки.** Code review, санитайз и тесты
  выполняются и отражаются отдельно.
- **Продолжение в новой сессии.** Агент сверяет файлы и состояние задачи,
  показывает оставшуюся работу и повторяет устаревшие проверки.
- **Явные решения.** Агент согласует план; push и merge требуют отдельных
  разрешений. Новые интеграции не подключаются автоматически.

## Быстрый старт

1. Установи плагин для своего агента по [инструкции](docs/INSTALLATION.md).
2. Открой папку проекта и вызови setup:

| Codex | Claude Code | Gemini CLI |
| --- | --- | --- |
| `$etask setup` | `/etask:etask setup` | `/etask setup` |

3. Выбери **local** или **github** и опиши цель. Например:

> Хочу локальное приложение учёта расходов. Можно добавить расход,
> выбрать категорию и посмотреть сумму за месяц. Данные остаются на устройстве.

4. Согласуй предложенные задачи, проверки и изменения AGENTS.md.
5. Запусти первую задачу, например `$etask ET-1`, и согласуй её план.

Setup всегда спрашивает режим и цель, даже если нашёл Git-репозиторий.
Он сохраняет существующие инструкции и показывает конфликты до записи.

## Local или GitHub

| | local | github |
| --- | --- | --- |
| Работа без удалённого репозитория | Да | Нет |
| Локальный Git | По явному выбору | Обязателен |
| GitHub CLI и авторизация | Не нужны | Нужны |
| Где хранится список задач | Markdown в проекте | Markdown в проекте |
| Завершение задачи | Критерии, review, санитайз и тесты | То же и смёрженный PR |
| Jira | Только по отдельному запросу | Только по отдельному запросу |

Для инструментов etask нужен Node.js 22+. Установленный плагин не требует
npm install. Инструменты самого проекта могут иметь свои зависимости.

## Как выглядит доска

| К выполнению | Выполняется | Тестируется | Выполнено |
| --- | --- | --- | --- |
| ET-3 — Отчёт по месяцу | ET-2 — Категории расходов | ET-1 — Добавление расхода | — |

Это иллюстрация, а не автоматически создаваемые задачи.
Бэклог хранит описание, критерии и зависимости; доска отображает его состояния.
В github агент уточняет завершение по PR, поэтому сохранённый снимок доски
может отличаться от актуального отображения в чате.

## Команды

Ниже примеры для Codex. В Claude используй префикс `/etask:etask`,
в Gemini — `/etask`.

| Команда | Что делает |
| --- | --- |
| `$etask setup` или `$etask init` | Выбор режима, цели, задач и правил проекта |
| `$etask board` | Показать актуальную доску |
| `$etask status` | Показать задачи, этапы и блокеры |
| `$etask status ET-1` | Проверки и состояние одной задачи |
| `$etask ET-1` | Выполнить конкретную задачу |
| `$etask` | Выбрать следующую доступную задачу |
| `$etask resume ET-1` | Продолжить после перерыва |
| `$etask review ET-1` | Проверить результат и подготовить завершение |
| `$etask doctor` | Найти проблемы настройки |
| `$etask update` | Обновить установленный плагин текущего агента |

## Как проходит задача

1. Агент читает цель, задачу и правила проекта, затем предлагает план.
2. После твоего одобрения реализует только запланированное.
3. После каждой правки делает **code review** и **санитайз кода**.
   Исправление запускает этот цикл снова.
4. Выполняет unit, integration, e2e и остальные согласованные проверки.
5. Показывает результаты. Коммит возможен только после успешных тестов.
6. В github отдельно запрашивает разрешения на push/PR и merge.

При ошибке инструмента или среды агент сообщает конкретный блокер.
Непройденная проверка не превращается в успешную из-за отсутствия доступа.
Запись review в состоянии — отчёт агента, а не независимый аудит кода.

## Что хранится в проекте

Пути согласуются при setup. Пример структуры:

```text
AGENTS.md               правила разработки и Git
.etask/config.json      режим, пути и команды проверок
docs/PROJECT.md         цель и критерии результата
docs/BACKLOG.md         задачи и зависимости
docs/BOARD.md           Markdown-доска
docs/DECISIONS.md       принятые решения
docs/MANUAL_CHECKS.md   ручные сценарии
```

Локальные результаты проверок и логи исключаются из Git. На другом устройстве
агент восстанавливает контекст из документов и Git/PR, затем повторяет проверки.
Разрешения на push/merge из файлов не восстанавливаются.

## Если что-то не работает

- **Команда не появилась:** начни новую сессию и проверь установку плагина
  средствами своего хоста.
- **Найден профиль v1:** запусти setup и согласуй миграцию.
- **Проверки устарели:** после изменения файлов повтори review, санитайз и тесты.
- **Нет gh или GitHub недоступен:** github-режим покажет блокер; переход в local
  требует твоего выбора, а не выполняется автоматически.
- **Нет plan mode или нужного инструмента:** агент должен сообщить ограничение
  и согласовать дальнейшие действия.

Подробнее — [формат профиля](skills/etask/references/configuration.md),
[продолжение работы](skills/etask/references/resume.md) и
[инструменты](skills/etask/references/tools.md).

## Версии и обновления

Вызови `$etask update`, чтобы получить последний стабильный релиз для
текущего агента. Setup проекта не требуется. Агент проверит установку,
согласует постоянную папку версий, если она ещё не выбрана, скачает и проверит
архив через gh, сохранит прежнюю копию и проверит новую установленную версию.
Актуальная версия не переустанавливается, более новая не понижается.
После успешного обновления открой новую сессию.

Для самой команды update нужны GitHub CLI и доступ к GitHub даже в local.
Остальные local-команды работают без них. Ошибка установки может требовать
восстановления регистрации: инструмент покажет журнал и сохранённый пакет.
Подробнее — [обновление и восстановление](skills/etask/references/update.md).
Версии до появления update нужно один раз обновить обычным способом.

Каждый согласованный выпуск dev → main запускает semantic-release.
Версия определяется Conventional Commits. GitHub Release содержит
список изменений и архивы для трёх хостов.
[Смотреть выпуски](https://github.com/kArteraa/every-task/releases).

Наличие исходников в dev не означает, что версия опубликована.
Точные результаты тестов и границы совместимости описаны в
[отчёте проверки](docs/VALIDATION.md).

## Разработка

Для разработки и semantic-release нужны Node.js 22.14+ (ветка 22) или
24.10+ и npm. Runtime установленного плагина работает на Node.js 22+.

```sh
npm ci --ignore-scripts
npm test
npm run lint
npm run build
```

Отдельные уровни — npm run test:unit, test:integration и test:e2e.
Сборка создаёт три ZIP-файла в dist. Общие правила хранятся один раз
в skills/etask; адаптеры подключают один и тот же процесс.
