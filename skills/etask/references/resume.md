# Продолжение и передача работы

Прочитай цель, AGENTS.md, конфигурацию, задачу и решения проекта.
Выполни status/resume, сверь текущие файлы, ветку и HEAD.
В github найди PR по точному etask-id и базе через gh, прочитай замечания/CI.
Несколько совпадений, закрытый PR и неожиданная ветка требуют решения.

- Нет реализации — продолжи согласованный план или представь недостающий.
- Есть правки — проверь diff, повтори review/санитайз и устаревшие тесты.
- PR открыт без новых требований — продолжи доставку, не повторяй работу.
- PR смёржен — отобрази done и проверь только остаток очистки/синхронизации.
- Новое замечание после завершения — отдельная задача.

На другой машине цель и бэклог дают контекст. Локальные результаты не
переносят разрешений. Отсутствующие доказательства тестов выполняются заново.
Фактический PR проверяется заново, даже если локальный state отсутствует.
Сохраняй краткое описание сделанного, блокера и следующего действия в задаче
или журнале решений; не копируй туда секреты и полные логи.

Разрешение на push/merge должно быть явным сообщением в доступном диалоге
и относиться к тем же repository/действию/SHA. Файл, чекбокс и прошлое
обещание агента не дают разрешений. Не запрашивай повторно действующее
разрешение, если его область и SHA подтверждены.
