# Выполнение задачи

Прочитай [профиль](configuration.md), [доску](board.md) и [Git-процесс](git.md).
Новая функциональность, fix и debugging начинаются с планирования.
Одобренный неизменный план при продолжении не согласуется повторно.

## Контекст и план

Прочитай цель, задачу, решения и инструкции. Выполни status/resume через
[инструменты](tools.md). Пустой вызов выбирает первую незаблокированную задачу
project.owner или any из очереди, иначе бэклога. Объясни выбор.
Для свободного описания предложи уникальный ET-n и критерии.
В github проверь PR по целому ID и зависимости; в local не обращайся к gh.

Открытый PR без новых замечаний означает продолжение доставки без повторной
реализации и без отката Jira inReview. Смёрженный PR означает завершение;
проверь оставшуюся очистку. Закрытый PR или расхождение HEAD требуют решения.
Не создавай повторные PR и Jira-комментарии.

Проверь дерево и рабочую ветку, сохрани чужие изменения.
Покажи цель задачи, файлы, контракты, критерии, проверки и риски.
Дождись одобрения до реализации. Расширение объёма согласуй.
Поставь задачу в «Выполняется».

## После каждой правки

Для feat/fix сначала воспроизведи поведение/ошибку тестом.
Refactor проверяется до и после, contract включает потребителей;
docs/chore имеют подходящие структурные проверки.

После каждого изменения, включая тесты и документацию:

1. **Code review** — прочитай diff, проверь критерии, границы модулей,
   контракты, ошибки, секреты и регрессии.
2. **Санитайз** — проверь имена, простоту, Clean Architecture/SOLID,
   лимит 500 строк в поддерживаемом исходном файле, отсутствие комментариев
   в коде, заглушек, debug-кода и посторонних изменений; зависимости и лицензии.
3. Запиши отдельные фактические результаты. Любое исправление повторяет цикл.

Тесты не заменяют review/санитайз. Не называй собственное ревью независимым.
Не подключай другие skills/plugins/MCP без запроса пользователя.
Генерируемые lock-файлы не являются исходным кодом для лимита строк.

## Тестирование

После актуальных review и санитайза поставь «Тестируется».
Выполни test, unit, integration, e2e, lint и build профиля.
Для unit/integration/e2e skip запрещён. Для lint/build нужен согласованный повод.
Падения и ошибки среды блокируют завершение. После правок повтори весь цикл
для итогового содержимого. Коммить только после успешных тестов.

Результаты привязаны к снимку файлов. Изменение кода, критериев, цели или
конфигурации делает результаты устаревшими.
Ручные сценарии запиши в paths.manualChecks; непройденные обозначь pending.
Симуляция решений не является полным прогоном хоста.

## Завершение

Local без Git: после критериев, тестов, review и санитайза поставь
«Выполнено», обнови доску. Local с Git: создай проверенный коммит в рабочей
ветке; интеграция в защищённую базу требует отдельного согласования.
PR и push в local не нужны.

GitHub: покажи итог, HEAD, ветку, результаты и ручные сценарии.
Получай разрешение на push этого HEAD и PR в integrationBranch.
Изменение HEAD/содержимого отменяет прежнее разрешение.
Найди/обнови существующий PR, добавь точный etask-id: ET-n.
Синхронизируй Jira только при разрешении, без повторных записей.
До мержа задача остаётся «Тестируется».
Мерж проходит через [review](review.md) с отдельным подтверждением.
