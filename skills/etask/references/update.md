# Обновление etask

Явный вызов update разрешает получить последний стабильный GitHub Release
kArteraa/every-task и обновить существующую установку etask текущего хоста.
Команда работает без setup, .etask/config.json, Git и Jira в целевом проекте.
Не создавай задачу update, не запускай setup и не меняй документы проекта.
GitHub доступен только через gh; другие навыки, MCP и браузер не разрешаются.

## Определение установки

1. Определи хост по текущей сессии. Не обновляй все хосты сразу.
2. Найди корень установленного пакета по пути активного SKILL.md:
   корень содержит skills/etask/SKILL.md и манифест хоста. Не подставляй
   checkout разработки вместо установленного пакета.
3. Проверь help и JSON-вывод штатного CLI. Codex: plugin list --marketplace
   every-task --json и plugin marketplace list --json. Claude: plugin list
   --json и plugin marketplace list --json. Gemini: extensions list
   --output-format json. Нужна ровно одна включённая установка etask.
4. Codex и Gemini обновляют пользовательскую установку. Для Claude сверяй
   scope (user/project/local) и projectPath с текущим проектом. Managed,
   отключённая, неизвестная или неоднозначная установка требует решения,
   а не удаления/включения по умолчанию. Не выдумывай другую команду при
   несовместимом CLI.
   При scope project/local штатный CLI изменяет регистрацию хоста в этой
   области; цель, бэклог, доска и .etask/config.json не меняются.
5. Согласуй постоянный каталог хранения скачанных версий, если его ещё
   нет в контексте предыдущего обновления. Он должен находиться вне проекта,
   Git checkout, установленного пакета и корня marketplace. Не используй
   временный каталог ОС: хост будет ссылаться на подготовленный пакет.

## Запуск

Из каталога целевого проекта запусти инструмент установленного навыка,
передавая аргументы отдельно, с корректным экранированием для shell:

```text
node <skill>/tools/etask.mjs update --host codex --scope user --installed-root <package> --store <permanent-directory>
```

Для Claude host=claude, scope берётся из установленной записи. Для Gemini
host=gemini, scope=user. Все пути абсолютные. --root для update не используется.
Сведения хоста и манифест должны подтверждать одну версию. Нестабильная
или неизвестная установленная версия требует отдельного решения.

Инструмент получает releases/latest через gh, отклоняет draft/prerelease,
проверяет точный архив хоста и обязательный SHA-256. Равная или более новая
установленная версия заканчивает работу без скачивания и переустановки.
Тег разрешается в commit SHA, который сверяется с RELEASE.json.
ZIP распаковывается только после проверки целостности, лимитов, путей,
дубликатов и типов файлов. Поддерживается обычный ZIP store/deflate,
создаваемый сборкой etask; ZIP64, шифрование, ссылки и другие форматы запрещены.

До изменения регистрации создаются previous/ и update.json: прежний пакет,
сведения о версии, scope, регистрации, SHA и подготовленном пакете.
Служебные .git, node_modules, dist, .superpowers и .etask в старом кэше
не копируются: резервируется содержимое плагина, а не репозиторий разработки.
Редактируемый исходный каталог и активный кэш вручную не перезаписываются.
Codex/Claude переподключают только marketplace every-task с единственным
плагином etask к новому локальному пакету. Gemini выполняет установку
подготовленного локального расширения. Сетевые URL хостам не передаются.
Успех означает проверенную новую версию в JSON-выводе CLI, а не только exit 0.

## Ошибка и восстановление

Ошибка до переподключения оставляет регистрацию нетронутой. При ошибке
штатной установки или проверки покажи фактический результат CLI и путь
Recovery journal. Не называй неудачный или частичный запуск успешным.
Журнал содержит прежнюю регистрацию и отдельную сохранённую копию пакета.
Автоматический rollback не обещается: удалённый источник, область установки
и требования хоста могут отличаться. Согласуй восстановление из previous/
штатными командами, не редактируй конфиги хостов вручную.
Если Gemini запросил доверие локальному каталогу, передай пользователю
этот конкретный запрос; не меняй глобальные настройки доверия.

Параллельный update в одном store блокируется update.lock. При аварийном
завершении сначала проверь процесс и журнал; не удаляй lock вслепую.
Старые версии, загрузки и журналы автоматически не удаляются.

После успеха покажи старую/новую версии и ссылку на релиз. Попроси открыть
новую сессию: текущая продолжает использовать ранее загруженные инструкции.
Первая установка версии с update делается обычным способом: старый skill
не может получить новую команду до обновления самого пакета.
