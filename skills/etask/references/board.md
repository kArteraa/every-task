# Задачи и Markdown-доска

Сначала пользователь формулирует и согласует цель проекта. Из неё агент
предлагает задачи с результатом, проверяемыми критериями и зависимостями.
Без согласования задачи не становятся планом реализации.

Бэклог — источник данных. Каждый блок начинается с `## ET-12 — название`.
Обязательны поля Тип, Исполнитель, Состояние, Зависимости, описание и критерии
в виде Markdown checkbox. Зависимости — `нет` или ID через запятую.
Сохраняй целые ID: ET-1 и ET-12 — разные задачи. Циклы и неизвестные ID запрещены.
Старый несовместимый формат преобразуется только через согласованную миграцию.

| Внутреннее значение | Колонка | Значение |
| --- | --- | --- |
| todo | К выполнению | Задача согласована, реализация не начата |
| in-progress | Выполняется | Реализация по одобренному плану |
| testing | Тестируется | Review/санитайз выполнены, идут проверки или проверка PR |
| done | Выполнено | Все критерии/проверки пройдены, в github также смёржен PR |

Переходы: todo → in-progress → testing → done. Исправление возвращает testing
в in-progress. Done не переоткрывается автоматически: новая работа — новая задача.
Блокер отображается отдельно и не вводит пятую колонку.

В local завершённость зависимости подтверждается сохранённым результатом,
а не одной надписью done. При переносе проекта без локальных свидетельств
агент проверяет историю и согласует восстановление, не выдумывает результаты.
В github доказательство зависимости — смёрженный PR в integrationBranch.

Доска строится из бэклога командой board. Local сохраняет её в paths.board.
В github актуальное отображение уточняется через gh, включая PR после мержа;
оно доступно в чате и не требует записи в защищённую ветку.
Сохранённый Markdown-снимок обновляй в рабочей ветке вместе с задачами
через инструмент board --save. Запись в защищённой ветке блокируется.
Не веди две независимо редактируемые базы статусов.
