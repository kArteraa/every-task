# Ревью

Прочитай цель, задачу, профиль, [пайплайн](pipeline.md) и [Git-процесс](git.md).
Проверь diff, критерии, контракты, ошибки, безопасность и документацию.
Отдельно проведи санитайз и запусти все checks. Исправление повторяет цикл.
Покажи реальные замечания и статусы ручных сценариев.

## Local

Не требуй PR и не запускай gh. Проверь файлы и локальный Git, если он включён.
Завершение требует критериев, актуальных тестов, review и санитайза.
Без Git обнови бэклог и доску. При Git сохраняй результат в рабочей ветке;
несогласованная интеграция в защищённую базу остаётся отдельным этапом.

## GitHub

Найди PR по точному ID и integrationBranch. Неоднозначность требует уточнения.
Прочитай head/base SHA, комментарии и CI. Получай ветку только при чистом
дереве; чужие изменения автоматически не исправляй.
Внешний review отправляй только при явном разрешении пользователя.
В собственный PR не отправляй approve/request-changes, покажи замечания в чате.

Дождись обязательного CI. Покажи repository/PR/base/head и запроси merge.
Повторно сверь SHA и CI перед действием. Используй --match-head-commit.
Не обходи защиту веток.

После MERGED проверь статус, синхронизируй разрешённую Jira, отобрази
актуальную доску и выполни только допустимую очистку.
Не коммить done напрямую в integration. Повтор выполняет только незавершённые
шаги. Выпуск в production требует отдельной явной команды.
