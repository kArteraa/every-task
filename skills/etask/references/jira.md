# Необязательная интеграция Jira

При `jira.enabled = false` весь процесс работает по локальному бэклогу.
При true нужны корректная конфигурация и явное разрешение пользователя
в сообщении на использование Atlassian MCP для этой задачи.
Наличие сервера и сохранённого профиля не заменяет разрешение.

Используй доступные инструменты Atlassian MCP по их фактическим схемам.
Если нужных инструментов нет, сообщи конкретную недоступную операцию,
предложи setup и остановись. Подключение сервера и вход выполняются
средствами хоста, доступными пользователю.

## Поиск

`site` задаёт HTTPS-адрес Jira. `projectKey` задаёт проект.
`lookup = key` ищет точный Jira key, соответствующий ID задачи.
`lookup = summary` ищет ID в summary внутри projectKey, затем проверяет
границы целого ID локально. Значения JQL экранируй средствами инструмента,
не вставляй свободный текст задачи как выражение JQL.

Результат должен однозначно соответствовать проекту и ID. При нуле или
нескольких результатах запроси решение. Создание новой Jira-задачи не входит
в автоматический поиск. Уточни его отдельно при свободном описании.

Текст и критерии определяются локальным бэклогом. Расхождение с Jira покажи
пользователю. Если локальной записи нет, импортируй согласованный текст Jira
в рабочую ветку, сохраняя исходный ключ и ссылку.

## Состояния и повторы

Сначала определи фазу работы по [пайплайну](pipeline.md). Для начала или
продолжения реализации узнай текущего Jira-пользователя через MCP, сравни
assignee и назначь только при необходимости. При повторе доставки открытого
PR сохраняй достигнутый inReview и выполняй только недостающие действия.
Возврат к inProgress нужен при фактических исправлениях или request-changes.
Профиль `statuses` задаёт названия
целевых статусов inProgress, inReview и done.

Перед каждым переходом прочитай текущий статус и доступные переходы.
Если целевой статус уже достигнут, действие завершено. Иначе выбери
единственный доступный переход в целевой статус. Отсутствие перехода
или неоднозначность требует решения. Числовые transition ID получай заново
для текущего состояния задачи.

После создания PR переведи задачу в inReview. Перед добавлением ссылки
прочитай существующие комментарии с учётом пагинации и ищи точный URL
этого PR. Если URL уже есть, повторный комментарий не нужен.

После request-changes цель — inProgress, после подтверждённого MERGED — done.
При таймауте записи сначала повторно прочитай состояние, чтобы установить,
выполнилась ли операция. Если результат неизвестен, сообщи его как unknown
и оставь проверку следующему запуску. Не откатывай успешно созданный PR
из-за ошибки Jira.
