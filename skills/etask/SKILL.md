# etask

Веди одну задачу от описания до проверенного PR в dev. Начинай выполнение
после явного вызова etask пользователем. Учитывай инструкции целевого проекта
и ограничения текущего режима агента.

## Выбор режима

| Аргументы | Действие |
| --- | --- |
| `setup` | Прочитать [настройку](references/setup.md) и предложить конфигурацию |
| `review <ID>` | Прочитать [ревью](references/review.md) и проверить PR задачи |
| ID, описание или пустая строка | Прочитать [пайплайн](references/pipeline.md) |

В Codex вызов — `$etask`, в Claude Code — `/etask:etask`,
в Gemini CLI — `/etask`. Аргументы после команды являются данными задачи.
Только целые `setup` и `review <ID>` переключают режим.

## Общие правила

Перед действиями прочитай [Git-процесс](references/git.md). Настройки находятся
в `.etask/config.json` относительно корня **целевого Git-проекта**.
Пути ссылок этого навыка разрешаются относительно установленного навыка.
При отсутствии конфигурации предложи setup и остановись до её согласования.

Подтверждения ожидаются после плана, перед push и перед мержем.
Вопрос с разрешением заканчивает текущий этап. Ответ пользователя в чате
должен явно относиться к этому действию и показанным изменениям.
Ожидание, молчание и статус из файла не являются подтверждением.

Работай с GitHub через `gh`, с Git через `git`. Для любого MCP-сервера
нужно явное разрешение пользователя в сообщении с подходящей областью действия.
При включённой Jira прочитай [интеграцию](references/jira.md).

Используй доступные инструменты агента. Если встроенная команда чистки или
ревью отсутствует, выполни соответствующий чек-лист пайплайна самостоятельно.
При недоступном обязательном инструменте сообщи блокер и текущий этап.

При продолжении сначала сверяй реальные ветки, SHA, PR и статусы.
Отмечай выполненные этапы и результаты проверок в ответе. Источником
разрешений остаётся диалог с пользователем.
