# Установка etask

Выбери пакет своего агента. Для инструментов etask нужен Node.js 22+.
GitHub и Jira не нужны для использования плагина в local-проекте.
Получить архив можно на другой машине и перенести его локально.

## Пакет опубликованного релиза

Посмотри доступные выпуски через GitHub CLI:

```sh
gh release list --repo kArteraa/every-task
```

Выбери версию из списка. Например, после публикации v1.0.0 для Codex:

```sh
gh release download v1.0.0 --repo kArteraa/every-task --pattern etask-1.0.0-codex.zip --dir etask-download
```

Для Claude выбери архив с окончанием -claude.zip, для Gemini — -gemini.zip.
Распакуй пакет в постоянный пользовательский каталог. Не перемещай этот
каталог после регистрации локального marketplace.
Если нужный релиз ещё не опубликован, используй явно выбранную копию исходников.

## Исходники для разработки

GitHub доступен через gh, Git transport через git:

```sh
gh repo clone https://github.com/kArteraa/every-task.git -- --branch main
cd every-task
```

Main содержит выпущенный процесс, dev — интеграционные изменения.
До мержа новой функции выбирай её рабочую ветку явно.
Версия манифестов в исходниках может отличаться от версии архивов,
рассчитанной semantic-release. Для точной версии используй release-архив.

## Codex — глобально для пользователя

В терминале из распакованного каталога:

```sh
codex plugin marketplace add .
codex plugin add etask@every-task
codex plugin list --marketplace every-task
```

В новой сессии открой целевой проект и вызови `$etask setup`.
Локальный marketplace и установленный плагин доступны пользователю в разных
проектах; конфигурация задач создаётся отдельно в каждом проекте.
Команды проверялись на CLI 0.166.0; доступность в другом хосте проверяй по его help.

## Claude Code

В сессии Claude Code из каталога пакета:

```text
/plugin marketplace add ./
/plugin install etask@every-task
```

Выбери пользовательскую область установки, если нужна доступность во всех
проектах. В новой сессии целевого проекта вызови `/etask:etask setup`.

## Gemini CLI

Из каталога пакета:

```sh
gemini extensions install .
```

В новой сессии целевого проекта вызови `/etask setup`.
При конфликте имён точное имя видно в списке команд хоста.
Расширение включает общий skill и не требует установки runtime npm-пакетов.

## Первый проект

Setup всегда спрашивает local/github, цель и критерии результата.
Затем предлагает задачи, команды тестов и изменения AGENTS.md.
До согласования не создаёт файлы и не подключает Jira/MCP.
Local может работать вообще без Git.

## Обновление и удаление

В версии с поддержкой команды вызови `$etask update` в Codex,
`/etask:etask update` в Claude Code или `/etask update` в Gemini CLI.
Команда работает без setup проекта, проверяет последний стабильный релиз
через gh, сохраняет старый пакет и подтверждает установленную версию.
Постоянный каталог новых пакетов согласуется при первом обновлении.
Ошибки и восстановление описаны в [инструкции update](../skills/etask/references/update.md).

Первую версию, содержащую update, установи обычным способом.
Сначала проверь версию установленного пакета. Скачай выбранный новый архив
в отдельную папку, сохрани прежнюю версию до успешной проверки.
Обнови локальный marketplace/плагин средствами хоста и начни новую сессию.
`codex plugin marketplace upgrade every-task` обновляет Git marketplace,
но не содержимое произвольной локальной папки. Проверь фактическую
установленную версию через plugin list.
Не ставь одновременно копию skill и plugin, чтобы избежать двух команд etask.

Удаление плагина выполняется средствами хоста. Цель, задачи и настройки
целевых проектов при этом сохраняются. Не удаляй проектные документы
вместе с кэшем плагина.
