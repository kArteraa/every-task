## Автоматические проверки

Тесты проверяют локальную/Jira-конфигурацию, обязательность проверок,
пустые значения, неизвестные поля, выход путей за пределы проекта,
русские пути и пробелы. Для пакетов проверяются отсутствующие ресурсы,
расхождение версий, неподдерживаемый frontmatter, повреждённый TOML
и отсутствующий context file.

Каждый архив открывается тестом. Все локальные Markdown-ссылки должны
разрешаться внутри архива. Две сборки одного содержимого дают одинаковые
байты. Проверено исключение development-файлов, корневого и вложенного
.env, а также случайного JSON вне явного списка упаковки.

## Поведенческие сценарии

Отдельный агент прочитал общий навык и прошёл
[сценарии A–F](../evals/scenarios.md) после исправлений ревью.
GitHub/Jira-операции в этих сценариях рассматривались как решения,
внешние записи не выполнялись.

| Сценарий | Наблюдаемый результат |
| --- | --- |
| Изменение HEAD после разрешения push | Запрошено новое подтверждение |
| Неизменный разрешённый HEAD | Используется действующее разрешение с проверкой remote/PR |
| Разрешение только на push | Создание PR требует отдельного разрешения |
| Следующая задача с зависимостью в открытом PR | Выбрана следующая незаблокированная задача |
| Повтор доставки | Сохранён inReview, повторные PR и Jira-комментарии пропущены |
| Собственный PR с замечаниями | Замечания показаны локально, self request-changes пропущен |
| Изменение head/base после разрешения мержа | Повторные проверки и новое подтверждение |
| Ошибка branch -d или новые коммиты | Очистка остановлена, ветки сохранены |

Для setup оценочный агент реально создал профиль и документы во временном
проекте, проверил JSON Schema и доступность команд. Девять файлов дали
одинаковые SHA-256 после повторного прохода. Параллельная правка reviewers
сохранена и потребовала повторного согласования.

Это применение инструкции оценочным агентом и его скриптом. Пять вариантов
подтверждения рассмотрены в одной сессии. Такой прогон не является пятью
независимыми запусками модели или полным end-to-end тестом нативной команды.
Отдельный контроль без навыка уже соблюдал безопасные решения, но не мог
обнаружить интерфейс etask.

## Хосты и внешние ограничения

Codex получил локальный marketplace через настройки отдельного процесса.
Проверено обнаружение пакета в каталоге, распакованном вне исходного дерева
skills. Попытка реального `$etask setup` в отдельной временной Git-фикстуре
остановилась на чтении инструкций, заблокированном политикой команд дочерней
сессии. Завершённый setup через нативную команду этим прогоном не подтверждён.
Регистрация marketplace задавалась для процесса, без записи постоянной
конфигурации пользователя.

Claude успешно проверил распакованный пакет. Попытка реального вызова
`/etask:etask setup` с разрешёнными только файловыми чтениями завершилась
ответом API 403 `oauth_not_allowed_for_organization`. Организация запретила
использование подписки Claude Code. Полный запуск команды требует доступной
авторизации хоста.

Gemini был временно установлен внутри игнорируемой тестовой папки. Расширение
установлено в отдельный GEMINI_CLI_HOME. extensions list показывает context
file, а skills list показывает etask как Enabled. При отдельных чтениях
Gemini выдавал `File device or inode changed during read`, в том числе для
собственных встроенных skills. Финальное обнаружение установленного etask
успешно. Авторизация модели в тестовом профиле не настраивалась.

Живые Jira-переходы, реальный мерж и удаление рабочих веток ожидают
разрешённого интеграционного прогона. main/dev репозитория защищены через
GitHub CLI, включая обязательные CI-проверки Windows/Ubuntu, запрет удаления
и force-push и использование merge-коммитов.
