# Выпуски etask

Рабочие PR направляются в dev. Выпуск dev → main создаётся и мержится
только по явной команде владельца. Dev сохраняется.

## Conventional Commits

| Изменение | Версия |
| --- | --- |
| fix, perf | patch |
| feat | minor |
| type! или footer BREAKING CHANGE: | major |
| docs, chore, test, refactor, style, build, ci, revert | patch |

Наибольший уровень среди коммитов определяет релиз. Неизвестный формат
блокирует выпуск; сообщения merge-коммитов не являются изменениями продукта.
Все поддерживаемые типы входят в список изменений. Автор — пользователь,
Co-Authored-By и другие упоминания агента в метаданных не добавляются.

## Автоматический выпуск

Workflow Release запускается на main и обрабатывает очередь невыпущенных
коммитов основной линии истории после базового 0.1.0. Каждый SHA проверяется
по смёрженному PR dev → main этого репозитория. Для него создаётся отдельный
Git-снимок с внутренней веткой release-snapshot и локальным bare remote.
Semantic-release 25.0.9 рассчитывает версию в dry-run именно для этого SHA,
независимо от дальнейшего продвижения GitHub main.
Адаптер анализирует Conventional Commits и использует gh для GitHub Release.
В снимке устанавливаются зависимости из его lock-файла через npm ci --ignore-scripts,
проходят tests/lint/build, затем собираются версионированные архивы его исходников.
Git-тег отправляется через git, публикация выполняется через gh.
Служебная ветка release-snapshot существует только во временном локальном репозитории.
Main/dev на сервере этот процесс не изменяет. MCP/HTTP-клиент не используются.

Первый запуск создаёт исторический тег v0.1.0 на уже выпущенном коммите
1414dbd38d6cfdb4f268707c13b0b4b03e991ae2, если релизных тегов ещё нет.
Это база расчёта версии, не повторная публикация старой версии.
Текущая миграция конфигурации является BREAKING CHANGE и даёт 1.0.0.
Обычный feat без несовместимого изменения дал бы 0.2.0.

Публикуются тег, GitHub Release, три ZIP-архива и CHANGELOG.md.
В каждом архиве версии адаптеров одинаковы, есть RELEASE.json с SHA и changelog.
Версии выставляются в артефактах; production не получает служебных коммитов.
Версия исходного дерева означает версию разработки. Для точной версии релиза
устанавливай архив из GitHub Release, а не копию main.

Публикация проходит через draft и загрузку всех файлов. Повтор после сбоя
восстанавливает недостающие выпуски по порядку и дополняет draft.
Опубликованный release автоматически не перезаписывается.
Каждый запуск читает актуальную main, а не только SHA своего события.
Продвижение main во время обработки добавляет новые SHA в следующий проход.
Даже если GitHub заменил ожидающий concurrency-запуск более новым, история
сохраняет очередь. Workflow_dispatch и повтор завершат все невыпущенные SHA.
Ошибочный SHA блокирует последующие выпуски до исправления причины.

## Проверка без публикации

`npm run test:e2e` запускает настоящий semantic-release в dry-run против
временного локального Git remote. Тест проверяет расчёт версии и отсутствие
нового тега. Он не доказывает доступность GitHub Actions/token/branch protections.
Первый реальный выпуск нужно подтвердить по завершённому workflow и артефактам.
