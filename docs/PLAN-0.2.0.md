# План etask 0.2.0

Имя плана сохранено. После выбора Conventional Commits миграция профиля v2
классифицирована как BREAKING CHANGE; рассчитанный первый выпуск — 1.0.0.

План согласован пользователем 9 ноября 2026 года. Задача ET-1.
Рабочая ветка feat/etask-project-workflow. Push и merge требуют отдельных разрешений.

## Цель

Сделать etask переносимым процессом разработки с обязательным выбором local/github,
целью проекта, Markdown-доской и проверяемым продолжением работы между сессиями.

## Согласованные требования

- Setup всегда спрашивает режим и цель, затем согласовывает задачи и настройки.
- Markdown-доска имеет колонки «К выполнению», «Выполняется», «Тестируется», «Выполнено».
- После каждой правки обязательны отдельные code review и санитайз. Исправления повторяют цикл.
- AGENTS.md получает предоставленный пользователем Project Instructions и правила Git.
- Нужны status, resume, doctor, проверка ID, зависимостей, переходов и актуальности доказательств.
- Интеграционная ветка и команды проверок настраиваются явно. Jira остаётся необязательной.
- Проверки включают unit, integration, e2e инструментов и отдельные наблюдения хостов.
- README объясняет пользу, установку, первый проект, команды и решение проблем.
- Conventional Commits заменяют прежние сообщения списком.
- Каждый разрешённый merge dev → main запускает semantic-release и публикует список изменений.

## Реализация

1. Настроить текущий проект по согласованному профилю v1 и сохранить цель/бэклог.
2. Добавить схему v2, явную миграцию, Markdown-задачи и построение доски.
3. Добавить переносимые Node.js-инструменты диагностики, состояния и продолжения.
4. Обновить инструкции setup/задач/review/Git и шаблон AGENTS.md.
5. Покрыть инструменты и процесс unit/integration/e2e сценариями.
6. Настроить semantic-release, Conventional Commits, выпуск архивов и changelog через gh.
7. Обновить все адаптеры, упаковку, версии и пользовательскую документацию.
8. Выполнить полный набор проверок, отдельные review/санитайз и показать итог перед push.

## Решения реализации

- Node.js 22, встроенные модули для устанавливаемых инструментов, без runtime npm install.
- Markdown-бэклог — источник задач; доска строится из него, без второй независимой базы статусов.
- Сохранённые результаты привязаны к содержимому проекта. Файлы не выдают разрешения на push/merge.
- Релиз изменяет версии в архивных артефактах; служебных коммитов прямо в main нет.
- fix/perf дают patch, feat — minor, BREAKING CHANGE или ! — major.
- docs/chore/test/refactor/style/build/ci/revert дают patch, чтобы каждый выпуск содержал релиз.
- Первый автоматический релиз опирается на ранее опубликованный main 0.1.0.

## Критерии готовности

- Local работает в проекте без origin, gh и Jira.
- Повторный setup сохраняет существующие инструкции и требует согласования конфликтов.
- Board/status/resume/doctor доступны из установленного пакета каждого хоста.
- Нельзя завершить задачу с незавершёнными зависимостями или устаревшими проверками.
- Новая правка отменяет актуальность review/санитайза/тестов предыдущего содержимого.
- npm test, npm run lint и npm run build проходят; артефакты самодостаточны.
- Релиз проверен на локальной фикстуре без публикации; реальные host/MCP ограничения указаны отдельно.
