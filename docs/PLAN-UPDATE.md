# ET-2 — Команда обновления etask

Статус: согласован пользователем; реализация подготовлена к проверке и доставке.
Ветка: feat/et-2-plugin-update, база dev 660b2b1.

## Результат

Пользователь вызывает `$etask update` в Codex, `/etask:etask update`
в Claude Code или `/etask update` в Gemini CLI. Агент обновляет установленный
плагин текущего хоста до последнего стабильного GitHub Release etask
и показывает проверенную версию и необходимость новой сессии.

## Поведение

1. Распознавать update до проверки проектного профиля. Команда доступна
   без setup, Git-репозитория и .etask/config.json. Не создавать задачу
   с названием update и не мигрировать проекты при обновлении плагина.
2. Определять текущий хост, установленную версию, источник и область установки.
   При неоднозначности запрашивать недостающие сведения, не выбирать каталог
   или другой хост молча. Обновлять только существующую установку etask.
3. Через gh получить последний опубликованный стабильный релиз
   kArteraa/every-task. Не использовать dev, draft и prerelease.
   Вызов update явно разрешает обращение за выпуском даже из local-проекта;
   остальные local-команды по-прежнему не обращаются к GitHub.
4. Если версия уже актуальна, закончить без переустановки. Не выполнять
   автоматический downgrade более новой или разрабатываемой версии.
5. Скачать архив соответствующего хоста в отдельный каталог. Проверить
   версию, SHA релиза, контрольную сумму и безопасность путей архива
   до установки. Ошибка загрузки или проверки сохраняет старую установку.
6. Установить проверенный пакет штатными средствами текущего хоста,
   сохранив прежнюю копию и сведения о регистрации для восстановления.
   GitHub читается только через gh; не передавать сетевые GitHub-источники
   сторонним менеджерам как обход этого правила. Не перезаписывать
   редактируемый checkout или кэш работающей версии вручную.
7. Проверить установленную версию средствами хоста. При сбое сообщить
   фактическое состояние и возможность восстановления; не объявлять успех.
   После успеха показать старую/новую версии, релиз и указание открыть новую сессию.

## Проверки

- Unit: сравнение версий, выбор стабильного релиза и архива, отклонение
  некорректных метаданных и опасных путей.
- Integration: вызовы gh и адаптеров хостов, актуальная версия без изменений,
  недоступные инструменты, ошибки скачивания/установки/проверки.
- E2e: обновление из изолированной старой установки, сохранность предыдущей
  версии при сбое и отсутствие изменений проектных файлов.
- Нативные прогоны хостов учитывать отдельно от фикстур: Codex и Claude CLI
  доступны на текущей машине, Gemini CLI пока не обнаружен.
- После изменений отдельно выполнить review и санитайз, затем test,
  unit, integration, e2e, lint и build.

## Границы доставки

Первую версию с update потребуется один раз установить обычным способом:
старый skill не получает новую команду до обновления самого плагина.
Реализация команды не означает автоматическую смену глобальной установки
на этой машине. Push/PR, merge в dev и выпуск в main согласуются отдельно.
